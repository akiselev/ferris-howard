# FH Substrate Survey: What We Haven't Designed Yet

**Status:** Draft 0.1 · The diagnostics doc was one member of a class — load-bearing, unglamorous, cheapest to design before the repo is old. This survey names the rest of the class, each with its core design question and a priority note. Ordered roughly by how soon its absence hurts.

## S1 — Proof caching and the swarm build problem
Agent swarms multiply builds; naive swarms re-elaborate the world per agent. Beyond olean caching (table stakes, pinned toolchains, shared cache server), the missing piece is a **proof cache keyed by goal hash**: tactic-block results content-addressed by (goal, local context, environment fingerprint), so any agent hitting a previously-closed goal gets the term instantly — ccache for mathematics. Sub-question with real subtlety: environment fingerprinting must be coarse enough to hit and fine enough to be sound (a simp-set change invalidates what?). Priority: high, and design-now because the cache key discipline constrains how tactics are invoked. Bonus: the cache *is* a corpus — cache statistics feed the Atlas proof-shape index for free.

## S2 — Reproducibility and the ten-year artifact
The referee pack promises re-checkability; nothing yet guarantees it survives a decade. Needed: a **lockfile for mathematics** (toolchain + Mathlib rev + FH prelude + statement hashes + cert hashes in one manifest), hermetic build definitions (nix-or-container pinning), and an archival standard: the published artifact bundles everything needed to re-verify on a machine that has never seen the internet. The validity program's drift monitor detects change; this is its complement — the ability to *reconstruct the past exactly*. Priority: the manifest format lands with couette G6; hermetic packaging before the first paper ships.

## S3 — Semver for meaning
Part V made trust propagate; nothing yet defines what a *version* of a theorem library is. Proposal to develop: semantic versioning where the semantics are semantic — statement change or hypothesis strengthening = major; new lemma = minor; proof golf, performance, doc = patch; and — the FH-specific tier — *regime narrowing* on an `Effective` artifact = major even when no statement changed. Machine-checkable by construction: the freeze hashes and elaborated-term snapshots already distinguish the tiers, so `fh publish` can *compute* the version bump instead of trusting the author. Nobody has semver where the compiler decides the bump; we can. Priority: medium; design before the first external consumer.

## S4 — Security: the adversarial supply chain
Nobody threat-models math libraries; agentic formalization forces it. Four surfaces: **axiom smuggling** (a transitive dependency introducing an axiom the whitelist audit must catch corpus-wide, not per-project); **lemma typosquatting** (near-name plausible-statement lemmas that are subtly wrong — the trust graph plus mandatory dossiers on imports is the countermeasure); **certificate provenance** (sign certificates and dossiers sigstore-style, so "kernel-checked" is verifiable as *whose* kernel, which toolchain, when); and the novel one — **prompt injection through the corpus**: agents read doc comments, ledger files, and error messages, all of which are attacker-writable in a dependency; agent harnesses must treat corpus text as data, never instruction, and the lint that enforces "no imperative language in doc comments of imported code" sounds absurd until the first incident. Priority: provenance signing with the first published artifact; the injection posture is a CLAUDE.md amendment today (one paragraph, zero cost).

## S5 — Cost accounting: the price of a theorem
The Effective type carries a cost axis; the *pipeline* doesn't. Every theorem should carry its production ledger: agent tokens, elaboration time, kernel time, search compute, human minutes — aggregated per declaration and per gate. Three consumers: budget routing (which targets are worth attacking at current prices — the priority list, made quantitative and self-updating); the meta program (§5's compressibility economics need real cost data); and honesty in publication ("this bracket cost X" is scientific information the field has never had). Priority: trivially cheap if instrumented from day one, painful to retrofit — instrument now.

## S6 — The differential fuzzer (Ruling D's enforcement engine)
Ruling D — legal-Rust-lookalike code never silently changes meaning — is currently a policy with a CI stub. Its real enforcement is a **differential fuzzer**: generate syntax valid in both real Rust and FH, parse with rustc's grammar and ours, and alarm on any divergence in structure that elaboration would accept silently. Same harness fuzzes the parser for crashes and the pretty-printers for round-trip (parse∘print = id — which simultaneously tests emit-lean and emit-latex fidelity). Priority: small standing harness, starts with M0, runs forever.

## S7 — Doctests: examples that cannot rot
Rustdoc's deepest cultural export: every documentation example is compiled and run in CI. Import it whole — every FH doc comment's example elaborates (and its `#eval`s check) on every build, so documentation cannot drift from truth. For a project whose thesis is *readable formal mathematics*, docs-that-are-checked isn't a nicety; it's the thesis applied to its own explanations. Priority: land with M0's comment syntax; free forever after.

## S8 — The editor: FH-analyzer
Everything so far serves agents; the human (there is one, learning both languages) needs rust-analyzer-grade LSP: hover showing elaborated types *and* the Lean rendering side by side (the Rosetta, live), inline goal view at `prove {` blocks, inlay hints for inferred regimes and instance resolutions (V10's invisible-elaboration audit, surfaced continuously instead of at vet time), jump-to-definition crossing into Mathlib. Priority: medium — bootstrap-mode Lean has its own tooling, so this can trail M0 by a season — but note the leverage: every elaboration-transparency feature built for the human editor is the same data the agent payload needs, one implementation, two consumers.

## S9 — Merge semantics for swarms & the bump-bot
Two smaller ones, named so they're not forgotten. **Namespace allocation and proof-merge policy** for concurrent agents beyond worktree isolation: who may write where, how two proofs of one lemma reconcile (answer: cache decides — first-verified wins, second becomes a cache hit). **The Mathlib bump-bot**: the drift monitor detects semantic change; the bump-bot *responds* — re-elaborate, bisect breakage to the causing upstream commit, apply mechanical fixes, escalate semantic ones with a drift report attached. The ecosystem's documented version-drift tax, converted from recurring crisis to scheduled chore.

## The pattern, named once
Every entry follows the same rule the diagnostics doc followed: the substrate is cheapest at repo age zero, each piece doubles as data for a layer we already designed (cache→Atlas, costs→Effective, fuzzer→emit fidelity, editor→agent payload), and none of it is speculative — each has a named precedent culture (ccache, nix, semver, sigstore, rustdoc, rust-analyzer, dependabot) being imported into mathematics rather than invented. The to-do list writes itself into M0's first month; the only design decision that can't wait even that long is S4's injection posture and S5's instrumentation hooks, both of which are a paragraph and an interface today.

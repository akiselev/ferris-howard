### B1 — `mem_upperBounds`, `bddAbove_def`

- `Mathlib/Order/Bounds/Basic.lean:35` and `:42`.
- Current binder (section-inherited, `:32`): `variable [Preorder α] {s t u : Set α} {a b : α}`
- Proposed: these lemmas need only `[LE α]`.
- Evidence: CONFIRMED (§45), novelty-screened.
- Source text: both are `Iff.rfl` (`a ∈ upperBounds s ↔ ∀ x ∈ s, x ≤ a`;
  `BddAbove s ↔ ∃ x, ∀ y ∈ s, y ≤ x`). The underlying definitions `upperBounds`,
  `BddAbove`, `IsLeast`, `IsLUB` are themselves stated under `variable {α : Type*} [LE α]`
  (`Mathlib/Order/Bounds/Defs.lean:30,34,39,45,51`), so the weakened statements are
  definition-consistent.
- `@[to_dual]` on both: `mem_lowerBounds` and `bddBelow_def` (also in the CONFIRMED
  pool, counted among the generated no-source entries) follow automatically.
- Risk: low for the statements; the edit is a section split (a `section LE` before the
  current `[Preorder α]` block), since the binder is inherited from `:32`, not written
  on the lemma. Whether every lemma moved into the new section elaborates was NOT
  verified (no build run — see Caveats).

## Caveats — read before submitting anything

1. **Term-level vs source-level.** PLAN.md C2, verbatim: *"Nothing counts until
   re-elaboration from source."* Every verdict in this document is term-level: the
   elaborated statement had one binder weakened, instance arguments were
   re-synthesized, and the kernel accepted either the original proof term (CONFIRMED)
   or a fresh tactic proof (PROVED). **No proposed source diff has been elaborated.**
   Section restructuring, `simp`-set divergence, instance-resolution order, `omit`
   semantics, and attribute expansion (`to_dual`, `to_additive`, `@[simp]`,
   `@[norm_cast]`) can each make a source edit fail even though the term-level check
   passed — and B13 shows the reverse failure too, where a term-level pass cannot even
   be *stated* at source level without generalizing an upstream definition. No
   `lake`/`lean` was run while preparing this document (a census holds the build).
2. **The pin has drifted.** All line numbers, binder texts, and section structures are
   from mathlib rev `905b9581` (v4.32.2). Before any PR: re-locate each declaration on
   current master, and re-check novelty there — a candidate may have moved, been
   renamed, or already been generalized upstream since the pin.
3. **One binder at a time.** Each pool entry weakens a single binder; joint or maximal
   weakenings were not computed. Where the result looks odd (S2 keeps `[Field α]`),
   that is the instrument's granularity, not a minimality claim.
4. **The novelty screen has a known blindness** (§68): it compares statements at the
   `Instances` erasure and misses structurally different formulations (an `Iff` prior
   art for an implication candidate, and vice versa). "Novel" means no equal statement
   at or below the target class in the 470,435-row closure — not that no human has
   ever stated the fact differently.
5. **PROVED tactics are certificates, not style.** Where the original proof fails, the
   recorded tactic (`aesop`/`simp`/`grind`) proves the weakened statement, but a PR
   should offer maintainers an explicit proof where they prefer one.
6. **Simp-set surface area.** Several candidates are `@[simp]` lemmas (B3, B5, B7,
   B13); weakening their binders widens where they fire. Only a full library build
   shows the consequences, and none was run.
7. **The locator is approximate.** Source matches are short-name + declaration-keyword
   greps; namespaces were hand-verified only for the selected entries. The
   119/22 "no source occurrence" counts and their generated/toolchain classification
   are heuristic except where stated (the two `WithTop.*_le_coe` cases were verified
   individually).
